# Design Fidelity Report: Overview/Today Screen vs Pulse × Liftoff / Nebula Mockups
**Last Verified:** 2026-09-04
**Verification Status:** Discrepancies Found

## Tooling note
Screenshot capture (`computer` action `screenshot`) failed intermittently and, for the mockup
tabs specifically, persistently with `Script injection timed out` / `CDP sendCommand
"Page.captureScreenshot" timed out` errors — this reproduced even on a pre-existing tab
(`localhost:5174`), so it is a session-wide contention issue (other concurrent agents sharing
this Chrome session), not specific to any one page. I did get several live-app screenshots to
render successfully. Separately, I found that `document.documentElement` reports
`getComputedStyle(...).colorScheme === "dark"` and a resolved background of `rgb(24,26,27)` even
immediately after switching the app's own "Darstellung" setting to **Hell** (confirmed via
`document.documentElement.getAttribute('data-theme') === "light"` at the same moment) — i.e.
something in this browser profile (most likely a Chrome-level forced/auto-dark-mode override) is
repainting the page regardless of the app's actual light/dark CSS, so screenshot colors in this
session cannot be trusted for exact hue judgments in either mode. To compensate, I read the
literal shipped CSS (`packages/client/src/styles/tokens.css`, `OverviewPage.vue`, `StatTile.vue`,
`ErholungszoneCard.vue`) directly — that source is what real users' un-tampered browsers actually
render, and it is unaffected by this session's rendering artifact. Structural facts from
screenshots (gradient presence, shadow presence/absence, card layout, corner radius, typography)
remain valid since those aren't things a forced-dark filter fabricates or removes.

## Matches
* **CTA gradient fill**: The primary action button (`.btn-primary`, e.g. "Jetzt trainieren →", "Zum Workout →") genuinely renders the intended three-stop blue→violet→magenta gradient (`var(--nebula-grad-cta)` = `linear-gradient(135deg,#2f9fe0,#8a6dff,#d63aff)`), and this is visually confirmed in a live screenshot, not just claimed from source. This is the one element where the mockup's "Nebula" identity shows up as more than a token definition.
* **Light-mode background and card-surface hue**: `--bg:#f6f4fb` / `--surface:#ffffff` in the shipped light theme are essentially identical to the mockup's `Nebula — Light` tokens (`--bg1:#f6f3fb`, `--surface:#ffffff`), and the light-mode card shadow token (`0 8px 20px -14px rgba(15,15,25,.18)`) is a byte-for-byte match to the mockup's light `.card` shadow. Light mode is much closer to spec than dark mode.
* **Structural layout**: The Overview page's card-stack rhythm (hero/launchpad card → status strip → progress tiles → feed, each card its own rounded surface with a pinned full-width CTA) matches the Pulse × Liftoff "Heute" screen's intended shape — single column, card-based, CTA-under-hero-content. This part of the design direction did ship.
* **Display typography intent**: A dedicated bolder/geometric display font (`Unbounded`) for headers and numerals vs. a plain body font (`Hanken Grotesk`) mirrors the mockup's `font-weight:800`, tight-letter-spacing headline treatment.

## Does Not Match / Partial
* **Dark-mode background is not violet-tinted**: The mockup's entire premise for "Nebula" reads as one continuous identity carried by a radial `#1c1a3a → #0a0912` violet-black wash across the whole phone screen. The shipped dark app background (`--bg:#0a0c14`) and surface (`--surface:#161c2d`) are both neutral blue-black with no violet channel bias and no gradient — confirmed both from `tokens.css` and from a rendered screenshot of `/profile` in dark mode, which reads as plain navy/black, not violet-black. This is the single biggest fidelity gap: the mockup's identity was meant to live in the *ground*, not just the accents, and in the shipped app it doesn't.
* **No colored glow shadows anywhere on Overview**: The mockup explicitly defines `--shadow: rgba(124,92,255,0.4)` (card) and `--shadow-strong: rgba(214,58,255,0.55)` (CTA) as part of Nebula's dark-mode identity — every card and the CTA button cast a violet/magenta glow. The shipped app *does* define matching tokens (`--nebula-glow`/`--nebula-glow-strong` in tokens.css, values identical to the mockup), but on the Overview screen they are used nowhere: `.launchpad`, `.tile`, `.erholungszone`, and `.btn-primary` all have `box-shadow: none` (border-only elevation). Grepping the whole client source, `--nebula-glow` is used in exactly one place app-wide: a transient `.streak-pulse` celebration animation in `App.vue`, not any standing Overview surface. So the "colored glow" half of the design intent exists as dead CSS variables, not as shipped surface treatment.
* **Streak/level accents are not Nebula**: tokens.css's own comment (line 165-168) states Nebula is for "Chrome, CTAs, streak/level accents, focus states." But `StatTile.vue` renders the streak value in solid `--fire-hi` (orange) and the level value in solid `--blue-hi` (blue) — plain, unrelated single-hue tokens, not the Nebula gradient in any form (not gradient-fill, not gradient-clip-text). This directly contradicts the design system's own stated scope for where Nebula should appear.
* **Rank/tier badge uses a different system entirely**: The mockup's rank card uses the Nebula gradient for both the hex-medallion badge and the gradient-clipped tier text. The shipped Overview's equivalent ("Gesamtrang" stat tile, `.panel-reward`) uses the pre-existing 9-tier color system (`--apprentice-1/2/3`, etc. — confirmed amber/bronze in the live screenshot for "Lehrling I"), which is a legitimate, separate design decision (documented in tokens.css as intentionally distinct — Nebula answers "is this interactive," tier-color answers "which of 9 tiers") but means the mockup's visual for this specific card (gradient hex icon) has no shipped counterpart on Overview at all.
* **Border radius drift**: mockup card/CTA radius is a uniform 20px; shipped app uses `--r-lg` (22px) for tiles, `--r-xl` (28px) for the launchpad/Erholungszone hero cards, and `--r-md` (16px) for the CTA button — three different values where the mockup used one. Minor but measurable, and the CTA specifically (16px vs 20px) is visually flatter/squarer than the mockup's pill-leaning cta.
