## Matches
* **CTA button gradient**: The Profile page's "Speichern" buttons (and the API-token save button) render a clean blue→violet→magenta gradient that visually matches the shipped `--nebula-1/-m/-2` tokens and is close in spirit to the mockup's gradient buttons ("Workout starten", "Weiter so!"). This is the one place the Nebula identity clearly made it into the shipped UI as more than a passing accent.

## Does Not Match / Partial
* **Rank/tier color scheme is bronze/orange and grey/silver, not violet-magenta**: The mockup's entire "Rang-Aufstieg" concept is built on one continuous violet→cyan/magenta gradient applied identically to every tier's badge, progress bar, and (in the finalists Nebula version) the tier-name text itself. The live `/ranks` page instead assigns each tier a distinct medal-like color: the "Lehrling" tier uses a bronze/orange gradient (`rgb(138,79,34)` → `rgb(224,138,60)`), and the "Sportler"/"Athlete" tier uses a grey/silver gradient (`rgb(105,116,138)` → `rgb(199,209,228)`), confirmed via computed styles on `.bar-fill` inside `.rank-progress.t-apprentice` / `.t-athlete`. This is a fundamentally different visual system — a per-tier "medal color" scheme rather than the single unifying gradient identity the Nebula direction was chosen for. Screenshots also show the current-rank row in the tier ladder highlighted in the same orange/bronze, and the "Rangaufstiege diese Woche" weekly-progress dots use plain grey/blue-violet flat circles, not gradient badges.
* **No gradient-clipped tier-name text anywhere on /ranks**: The finalists mockup's defining "Nebula" treatment for rank text is `-webkit-text-fill-color: transparent` over the 3-stop gradient (confirmed on the mockup's `.beat-tier` element). On the live app, every tier label inspected ("LEHRLING I", "LEHRLING III", "SPORTLER III") is plain solid-color text (`rgb(232,230,227)`-ish light grey/white), with no gradient background or text-fill-color trick applied. The tier-name-as-gradient-art concept from the mockup simply isn't present.
* **Badge/medallion is a small inline chip, not a centerpiece hexagon medallion**: In "Pulse × Liftoff," the rank badge is the visual anchor of its column — a large (~90px) hexagon with a bold gradient stroke and an icon inside, sitting above the gradient-clipped tier name. On the live app, the equivalent element is a small (~40px) square-ish/hexagon-cut icon chip sitting inline to the left of each exercise's name — a minor UI decoration, not a celebratory focal point.
* **Dark background is neutral blue-black, not violet-tinted** (previously established, reconfirmed here): live `body` background computes to `rgb(10,12,20)` (`#0a0c14`), not the mockup's `#1c1a3a`/`#0a0912`.
* **Light mode does not actually render light for rank surfaces (and beyond)**: Toggling "Hell" in Profil → Darstellung sets `document.documentElement.dataset.theme = "light"` and the `--bg` CSS custom property correctly resolves to `#f6f4fb` (a light lavender close to the mockup's "Nebula — Light" background), but the *actual rendered* `body`/`.tier-ladder`/`.rank-progress` background colors remain `rgb(24,26,27)` — a near-black color, not light at all. Screenshots show the outer app chrome turning light-grey/white while the rank ladder panel and exercise cards stay dark. This means the "Nebula — Light" mockup direction (solid deep-blue tier text on a bright near-white ground) is not being achieved even when the user opts into light mode — a rendering/theming bug independent of the Nebula-gradient question, but it further undermines the "fully shipped app-wide" claim for this screen.

## Unverified (Needs Further Manual Check)
* **Rank-up celebration / "Finish Sequence" screen**: Could not be captured in this session. Triggering a genuine rank-up requires completing a workout with a strong-enough performance to cross a rank threshold, which needs multi-step form interaction (selecting exercises, logging sets/weights) and risks colliding with other agents/the user's real account data active in the same shared Chrome session and dev server at the time of this audit. The static `/ranks` page (audited above) is the best available proxy and already shows the badge/gradient/background identity is not carried through with mockup fidelity; it is reasonable to expect the celebratory screen shares the same bronze/silver tier-color scheme and neutral dark background, but this was not directly observed and should be manually verified by someone able to complete a real workout end-to-end.
