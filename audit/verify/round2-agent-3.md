## Newly Discovered Issues
* **`GET /api/settings/gym` returns HTTP 500 on every page load.** Reproduced on a fresh reload via CDP network capture (`Network.responseReceived` showed `status: 500` for `http://localhost:5174/api/settings/gym`). This fires on initial app load (before any workout interaction) and did not block rendering (the app degrades silently), but it is a real, live, reproducible server error that neither audit round's static code trace flagged. Not investigated further (out of this task's scope), but worth a follow-up — `packages/server/src/routes/settings.ts`'s `GET /api/settings/gym` handler is the endpoint.
* **Vue warning on Overview page load**: `[Vue warn]: Extraneous non-props attributes (class) were passed to component but could not be automatically inherited because component renders fragment or text or teleport root nodes` on `<ErholungszoneCard class="tile--priority" ...>`. Fires every time `OverviewPage.vue` mounts. Cosmetic/non-fatal (the class simply doesn't get applied), but a real console warning invisible to a static-only audit.
* **JS-dispatched `.click()` on the RPE button silently no-ops; a real mouse-driven click works.** During testing, calling `element.click()` via `page.evaluate` on the `RPE` pill did not open the sheet (no error, no state change), while a Puppeteer `page.mouse.click()` at the same element's coordinates worked immediately. This is very likely an artifact of the test harness (synthetic vs. trusted click event) rather than an app bug — the sheet works correctly for real users — but is noted since it could mislead a differently-instrumented automated test into a false "broken" verdict.

## Unverified (Needs Further Manual Check)
* **`superset-continue` RestTimer state (no ring, no skip, "Weiter im Superset")**: Not triggerable with the available seeded routines — the "Test" routine (and the other routines visible in the routine list: "Push Test", "Fast Path Test", "Quick Legs", "RT Fast Test 2", "Muscle Coverage Test", "Lopsided Test") did not present as containing an active superset grouping during this session. Source code (`RestTimer.vue:94-99`) confirms the distinct compact template exists and is wired to fire when `logCurrentSet()` returns null (round not complete), but this needs a routine with real superset exercise-pairing to exercise live.
* **Finish Sequence Beat 1 (rank-up beat) — animated LP bar and `.badge-ring-muted` ring, side by side with a genuine (non-muted) rank-up in the same session**: Two live attempts (moderate and extreme weight/rep increases) both failed to produce a session rank-up — the moderate attempt's gain was too small, and the extreme attempt was correctly discounted by the plausibility engine to near-zero, so `sessionRankUps` stayed empty and Beat 1 was legitimately skipped (per its own "omitted entirely when the session had none" logic) both times. A precisely-tuned live rank-up (e.g., an exercise sitting exactly 1 LP short of its next division, logged with a small, plausible, non-flagged improvement) would be needed to visually confirm the animated bar and the muted-vs-genuine ring contrast side by side. The Overview page did show "1 LP bis zum nächsten Rang in Bizepscurls (KH)" earlier in the session, suggesting this is achievable with more careful data setup than time allowed here.
* **RPE/Notiz pill persistence across a full set-log cycle**: The `Notiz` pill's visual state after saving a note (does it show a filled/checked state?) was not confirmed — a save attempt was interrupted mid-flow by an unrelated Puppeteer `protocolTimeout` on a subsequent `page.click('textarea')` call (test-harness issue, not app issue; recovered by reconnecting), and the note text was not re-verified as persisted after recovery.
