## Unresolved & False Positives
* **`ThumbZoneAction` primitive is orphaned**: `packages/client/src/components/ui/ThumbZoneAction.vue` exists and is described in the closure note as a Foundation deliverable "every later phase builds on," but `grep -rn "ThumbZoneAction"` across the entire client `src` tree returns zero template usages (`<ThumbZoneAction`) — only the component's own file and two comments in `App.vue` referencing it conceptually. No page anchors its primary CTA using this primitive. The plan's Phase 0 success criterion implied broad adoption; this did not happen.
* **`DensityScope`/`useDensityMode` primitive is orphaned**: Same pattern — `components/ui/DensityScope.vue` and `composables/useDensity.ts` (`useDensityMode`) have zero consumers outside their own definitions. The plan's specific claim that Train/Plan/Progress screens use this "as a reusable layout prop rather than per-screen improvisation" is false — none of those screens use it at all.
* **`TruncatingLabel` adoption is incomplete, and one screen actively contradicts the fix it's supposed to guarantee**: Only one real consumer (`components/exercise/ExerciseRow.vue`, feeding the routine-wizard reorder list). `pages/RanksPage.vue`'s own exercise-name element still uses `overflow-wrap: break-word` (lines 237-241 of that file), which is the literal mid-word-break behavior lens-3 flagged and the plan says the primitive closes "at the primitive level so it cannot recur screen-by-screen." `WorkoutPage.vue`'s exercise-name renders (lines 368, 486) are plain text with no visible truncation handling. The claim that this bug "cannot recur screen-by-screen" is contradicted by at least one live screen.
* **Phase 0's five-zone Today/Train/Progress/Plan/Profile nav IA was never built**: The plan's Phase 0 spec explicitly calls for five bottom tabs (Today/Train/Progress/Plan/Profile) with Train conditionally shown only while `isActive`. The actual `App.vue` nav (`navItems`) is Overview/Workout/Ranks/Exercises/Profile — no dedicated "Plan" (routines) tab exists; routines are nested inside the Workout tab, and Runs was merged into the Workout tab per an in-code comment referencing a separate "engagement-audit-v3" rework, not Plan C. Nav items render unconditionally, not gated on `isActive`. The closure note is careful to only claim "nav-shell hardening" (matching commit `3e5fb78`, a touch-target-floor fix to the pre-existing nav), so it does not directly assert the five-zone IA was built — but a careless reader of the closure note's "Foundation... nav-shell hardening" bullet next to Phase 0's explicit five-zone spec could easily conclude the new IA shipped. It did not.
* **No automated tests exist anywhere in `packages/client`**: Zero `.test.ts`/`.spec.ts` files found. Several phase "success criteria" in the plan are written as testable assertions (e.g., "`useCountUp`/`useCelebrate` pass a reduced-motion snapshot test," "verified against the three code-specified cases in lens-2 §5"). None of these were verified via actual automated tests — the reduced-motion *code paths* exist and look correct on inspection, but "pass a...test" as literally claimed did not happen. The closure note discloses this gap honestly ("no live dev server was available... every visual/interaction check was a static code trace instead"), so this is not a hidden false positive, but it means every phase's stated success criterion should be read as "code-traced," not "tested."
